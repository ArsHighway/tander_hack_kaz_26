## Запуск

Настройки запуска находятся в `compose.cleaned.yaml`. Он задаёт отдельные образы,
очищенный КТРУ и один воркер. Локальный проект Compose — `tenderhack-cleaned`.

```powershell
docker compose -p tenderhack-cleaned -f docker-compose.yml -f compose.cleaned.yaml up -d --build
docker compose -p tenderhack-cleaned -f docker-compose.yml -f compose.cleaned.yaml ps -a
```

Интерфейс: http://localhost:8080. Нужно дождаться состояния API `healthy`.
Завершившийся с `Exited (0)` контейнер `migrate` — штатное выполнение миграций.

Для полного стенда, аналогичного проверенному локально, нужны отдельные данные:

```dotenv
CATALOG_PATHS=data/catalog/standards.json
EXEMPLARS_PATH=data/catalog/exemplars_syn.jsonl
EXEMPLAR_VECTORS_PATH=data/catalog/exemplars_syn.vectors.npz
TWINS_PATH=data/catalog/twins.sqlite
KTRU_PATHS=data/catalog/ktru_xml.cleaned.json
```

Эти большие исходные файлы и индексы не публикуются в Git. Нужны файлы по указанным
путям и векторный индекс основного справочника в PostgreSQL; подробности подготовки
основного справочника — `docs/plans/2026-10-06-standard-catalog.md`.
Без полного набора `.env.example` использует демо-категории, поэтому набор доступных
сценариев отличается от полного стенда. Ключи внешних моделей задаются только в локальном `.env`.

Остановка без удаления БД:

```powershell
docker compose -p tenderhack-cleaned -f docker-compose.yml -f compose.cleaned.yaml stop
```
