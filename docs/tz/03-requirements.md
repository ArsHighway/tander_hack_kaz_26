# Требования: чек-лист по критериям

Сверка методички ([01-methodology.md](01-methodology.md)) и критериев ([02-criteria.md](02-criteria.md)) с решением.
Состояние решения — аудит [../qa/2026-10-09-tz-audit.md](../qa/2026-10-09-tz-audit.md).

## Суть кейса

Поставщик вводит описание товара свободным текстом → модуль определяет характеристики по справочнику КТРУ,
сопоставляет значения и единицы, приводит к унифицированному виду, по шагам сужает множество кодов КТРУ до
конечного кода, находит ошибки (опечатки, несоответствия, несуществующие значения) с обоснованием и
исправлением, а при нехватке данных говорит, что дополнить. Категории хакатона: одежда, мебель, инструменты.
Превалирует справочник КТРУ.

## Чек-лист

| Критерий (баллы) | Что должно быть | Где у нас |
|---|---|---|
| Прототип (10) | веб-сервис: описание → характеристики → конечный код КТРУ | мастер `/`, `/api/v1/autofill`, `/answer` |
| Свободный текст (3) | произвольная форма, опечатки, неполные данные | `app/extract`, `textclean`, исправление опечаток BM25 |
| Подбор характеристик (6) | характеристики конкретного товара | характеристики позиции справочника, шаг 4 мастера |
| Значения и единицы (5) | верная интерпретация значений пользователя | `values.fit_value`, словарь единиц ОКЕИ |
| Поэтапное сужение (6) | логичное сокращение кандидатов | `narrowing.py`, шаги 2–3 мастера |
| Конечный код КТРУ (7) | правильный конечный код | второй этап `chain.ktru`, `ktru_code` в карточке |
| Неоднозначность и нехватка данных (3) | уведомление и конкретные шаги | `not_found_steps`, вопросы с вариантами |
| Опечатки (1) | раскладка, пропуски, перестановки в описании и характеристиках | `nearest_allowed`, опечатки значений |
| Несоответствия и несуществующие значения (8) | проверка на соответствие КТРУ | `checks/detector.py`, `/check` |
| Исправление ошибок (3) | корректное автоисправление | `fix` в замечаниях |
| Интерфейс в стиле портала (4) | цветовая схема и разметка Портала поставщиков (UI-кит Figma) | `DESIGN.md`, превью «Как на портале» |
| Наглядность характеристик (2) | видно, что извлечено, можно править | шаг 4, подсветка фрагментов |
| Наглядность сужения (2) | путь от описания к коду | полоса шагов, живая карточка |
| Сообщения (2) | понятные уведомления и ошибки | тексты замечаний и шагов |
| Архитектура (6) | рациональные компоненты | FastAPI + воркеры + RabbitMQ + Redis + pgvector, compose |
| Обоснование технологий (5) | выбор под задачу и ресурсы | `docs/math-model.md`, замеры |
| Скорость (5) | быстрый ответ | `/autofill` p50 ~0,5 с без модели |
| Понимание проблемы (7), презентация (15) | проблема, решение, архитектура, BPMN, ответы | `docs/bpmn/`, презентацию делает команда |

## Ограничения

- Linux и веб-интерфейс — compose на Linux-образах.
- Без платных поисковых API (Yandex Search API, Google Custom Search JSON API) — не используем.
- Без low-code и no-code платформ — не используем.
