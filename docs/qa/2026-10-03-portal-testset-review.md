# Ревью модуля на 5000 карточках портала (03.10.2026)

Набор: `data/testset/testset.xlsx` (`uv run python -m app.tools.build_testset`), 5000 СТЕ с zakupki.mos.ru,
825 категорий, три равные части по «лёгкости». Прогон: чтение xlsx нашими читателями, разбор строки
характеристик, извлечение правилами (`compare_card`, без LLM) против значений поставщика, проверки
модерации; затем три ревьюера прочитали все карточки своего уровня. Отдельно — 120 карточек через
`POST /api/v1/batch` с LLM и справочником из 128 категорий набора.

Ограничения набора: **описание пустое у всех 5000** (поиск каталога и `GetSku` его не отдают, на 20 из 20
пусто), поэтому проверено извлечение только из наименования. Перечень значений категории строится из
этих же карточек, редкие значения в нём отсутствуют. «Значение поставщика» — не эталон.

## Падения (чинить первым)

- `CharIn` (`app/schemas.py`: `MAX_CHAR_NAME=300`, `unit max_length=50`) валит реальные карточки:
  `POST /api/v1/batch` с testset.xlsx → **500** на весь файл (`batch._rows_of`); `portal_report` падает в
  `PortalCard.to_card_in`. 12 имён длиннее 300 знаков в 4 карточках, единица 57 знаков (#47358789).
  Нужно: проблемная строка → `failed`/замечание, а не исключение.
- `profanity`: ложный block мата на «Е6» (бита Torx «Е4, Е5, Е6», «Мегаомметр Е6-24») — цифра 6 читается
  как «б». Проверено: `find_profanity("Мегаомметр Е6-24") == "е6"`.

## Извлечение (`app/extract/rules.py`), по убыванию эффекта

1. Размеры «AxBxC ед.» и одиночные мм/см/м не извлекаются: ~2300 ∅ на трёх уровнях (27–36 % всех ∅).
   Значение помечается `compound`, мм/см/м нет в `moderation.UNIT_CHAR`. Порядок осей у поставщиков
   разный — учить по категории.
2. Спецификация без единицы пропускается (`_from_name`: `spec_unit is None`; проверено: «50 штук» при
   unit=None → [], при «шт» → 50). Единица в имени («Толщина, мкм») не берётся в `card_specs`
   (`split_name_unit`). `NAME_ALIASES` (Вес~Масса) в извлечении не используется.
3. Словарь единиц и пересчёт: литр(ов), пар, деталей, А·ч/мАч, Вт↔кВт, ГБ↔ТБ, дюйм, бар, «слойные»,
   `[0*]С`, `мм[2*]`; г/м2 против г у бумаги. «Количество X: N» («6 полок», «3 кнопки») — 287 ∅ на среднем.
4. Головное слово наименования как значение «Тип/Вид/Назначение» (52 % ✗ на сложном), одно слово в
   нескольких характеристиках, отрицание «без ртути» → «ртуть», бренд в кавычках как материал. Мусор из
   перечня с min_cards=1.
5. Цвета: «белая/синяя» не находят «Белый/Синий» (основа «бел» короче 4); коды с цифрами совпадают
   префиксом (CR123A → CR123). Нужен общий словарь цветов.
6. Тай-брейк `len(fits) != 1`: при «Мощность микроволн» и «Мощность гриля» — ∅.
7. Предметные шаблоны: шины «235/55 R18 104V», кабель «4х120мм2», лекарства, учебники, масла «5W-30»,
   размер одежды «52-54/182-188».

## Разбор строки характеристик (`app/ingest/characteristics.py`)

- «Имя:: значение» (имя с «:» на конце) → значение «:…»: 160 из 261 расхождений. Одна строка правки.
- Значения с «;» внутри (комплектации) рвутся на лишние характеристики; склейка меняет пробелы.

## Проверки модерации (`app/checks/`)

- Block «указана дважды» на законных многозначных атрибутах портала («Конструктивные особенности»,
  «Требования к комплектации»): ~200 сообщений. Block — только для одинаковых или противоречащих значений.
- «В наименовании нет значения и единицы» — на 63–79 % карточек, шум; цитата режется («1,4 кг/12»).
- Пропуски: единица против наименования («0,5 г» при «0,5кг», «110 Л» при «110 мл», «2500 кВт» у
  обогревателя), нули-заглушки, выбросы на порядок, «Белизна=-2147483647 %», чужая категория.

## Метрика (`app/portal/fill.py`) — занижает нас

- `same_value`: ~35 % ✗ на деле совпадают («жидкое» ⊂ «мыло жидкое», «5W30»/«5W-30», «10 (XL)»).
- `evidenced`: ложное «есть в тексте» по случайному числу (код модели, «5x50»), ложное «нет» без
  пересчёта единиц и для «5» против «5,0»; `PortalChar.numeric` по типу JSON, строковые числа теряются.

## Набор

- Описания нет — нужен вариант с описанием (докачка карточек с описанием или полусинтетика «Имя: значение»).
- Формула уровня считает булевы «Да/Нет» и случайные числа; лучше считать по тому, что правила способны взять.

## Раунд 3 (04.10.2026): подбор КТРУ на всех 5000 и требование «уведомить и предложить шаги»

Прогон: `autofill` по всем карточкам, справочник — 128 категорий набора, BM25 + векторы, без LLM.

| Исход | До раунда 3 | После |
|---|---|---|
| Код верный | 906 | 920 |
| Код чужой / при отсутствии категории | 29 / 63 | 29 / 54 |
| «Не найдено», хотя категория в справочнике | 569 | 485 |
| Вопрос, верная позиция среди кандидатов | 1 663 | 1 702 |

Что сделано по требованию ТЗ (`narrowing.py`, `pipeline.py`):
- «не найдено» больше не говорит общими словами: похожие позиции с совпавшими словами (только главное слово
  или два слова, без единиц и огрызков) либо «По слову «X» подходящей позиции нет…»;
- позиция ниже порога, но с тем же главным словом («Ноутбук Apple …» → «Ноутбук») — «Подтвердите позицию»,
  а не «не найдено» с ней же в похожих;
- кандидаты разных товаров («Аккумуляторы» и «Шины») или без различающих характеристик — выбор позиции, а не
  вопрос про «Категорию использования шины»;
- код без подтверждения не ставится, если главное слово есть только в значениях характеристик позиции
  («Ведро» у красок) или позиция — запчасти к самому товару («Проектор» → «Запасные части … к проекторам»);
- цвет, «артикул», «размер» не заставляют подтверждать позицию;
- в пакетной загрузке «нужен ответ» несёт сам вопрос с вариантами.
