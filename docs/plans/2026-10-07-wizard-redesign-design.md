# Новый интерфейс: мастер создания СТЕ

Спецификация после брейншторма 07.10.2026 (макеты — во вкладке визуального компаньона, сохранены в
scratchpad сессии). Исследование аналогов — `docs/research/ux-competitors.md`. Фильтр `antislop` в режиме
«во время работы».

## 1. Рамки

**Входит:** мастер «Создание СТЕ» (пять шагов), живая карточка справа, предпросмотр «как на портале», ввод
файлом (Word, PDF, Excel), фото в предпросмотре, группа «Общие сведения» (производитель, модель, страна), новая
тема и шапка для всего приложения.

**Не входит сейчас:** редизайн экранов «Массовая загрузка», «Мои заявки», «Модерация», «Метрики», «API» — они
получают только новую тему (шрифты, цвета, радиусы) и остаются на своей раскладке. Их макеты — следующий
брейншторм.

## 2. Решения пользователя (по ходу брейншторма)

| Вопрос | Решение |
|---|---|
| Раскладка экрана создания | **мастер по шагам** (из трёх вариантов: карточка+помощник, мастер, лента решения) |
| Визуальное направление | **свой продукт, без опоры на стиль портала**: вариант «как портал» сделан и отклонён (строго, «ИИ-шно») |
| Шрифт | **IBM Plex Sans** для текста, **IBM Plex Mono** для кодов (из плитки «Инструмент») |
| Фон | **только белый**, без бежевого |
| Акцент | **кобальт `#2547d0`** (из янтаря, изумруда, кобальта) |
| Живая карточка | **да**, справа, с шага 2; на телефоне — нижняя полоса |
| Предпросмотр | **да**, «как на портале», на шаге 5 и по ссылке из живой карточки |
| Файлы | **Word .docx и PDF с текстом** для одной карточки; Excel с одним товаром — в мастер, с несколькими — в пакет |
| Фото | только фото самого товара; без него — картинка категории с портала; фото похожих СТЕ — только подсказка |
| Общие сведения | **добавить**: производитель, модель, страна происхождения |
| Готовность | считает только обязательные характеристики позиции |
| Фото поставщика | **хранится на сервере** вместе с заявкой |
| Товар без КТРУ | показать «в КТРУ нет», оформить характеристики в формате КТРУ, код не выдумывать; спросить организаторов |

## 3. Дизайн-система (заменяет `DESIGN.md`)

Design Read: рабочая форма поставщика для создания карточки товара в госзакупках, для поставщиков и жюри
Департамента; язык — точный рабочий инструмент на белом; шкалы ENERGY 1 / RHYTHM 2 / MOTION 1.

**Цвет** (основной один, акцент один, остальное — смысловые состояния):

| Токен | Значение | Роль и причина |
|---|---|---|
| `ink` | `#14161b` | основной текст, тёмные кнопки-переключатели |
| `ink2` | `#3b414c` | вторичный текст, коды |
| `mute` | `#5f6773` | подписи (5,7:1 на белом, проходит AA) |
| `line` | `#e3e6eb` | все разделители; рамок у поверхностей нет, есть линии |
| `acc` | `#2547d0` | кобальт: главное действие, текущий шаг, выбранный вариант, ссылки |
| `acc-soft` | `#eef1fd` | фон выбранного варианта и текущего шага |
| `mark` | `#fff0b3` | жёлтый маркер: **только** «взято из вашего текста» |
| `err` | `#c4321f` | ошибка на поле |
| фон | `#ffffff` | страница; серых «столов» под карточками нет |

**Шрифт:** IBM Plex Sans 400/500/600, IBM Plex Mono 400/500/600 — из своих файлов (`@fontsource`), без
Google Fonts: демо работает без интернета. Причина: Plex — шрифт инженерных инструментов, коды и цифры в Mono
читаются как коды. Open Sans (`@fontsource`) — только внутри предпросмотра «как на портале», потому что так
выглядит сам портал.

**Форма:** радиусы 6 (кнопки, поля), 8 (списки, полоса шагов, панели), 10 (внешние блоки); теней нет, кроме
нижней полосы и мобильной шторки (они лежат поверх прокрутки). Сетка отступов 4/8/12/16/24.

**Мотивы продукта:** (1) полоса шагов показывает **результат** каждого шага с кодом, а не название шага;
(2) жёлтый маркер провенанса; (3) коды КПГЗ, ОКПД2, КТРУ, СПГЗ всегда моноширинным; (4) подсказки клавиш
(`1`…`6` — вариант, `Enter` — подтвердить, `Ctrl Enter` — заполнить).

**Запреты (antislop):** заглавные подписи с разрядкой, пилюли-бейджи без функции, карточка в карточке, тени на
всём, эмодзи, длинное тире в текстах интерфейса, кнопки «Далее» без глагола-действия, выдуманные цифры.

## 4. Мастер

Пять шагов: **Описание → Категория → Позиция КТРУ → Характеристики → Отправка.** Мастер открывается на первом
шаге, где нужен человек; шаги, которые модуль решил сам, отмечены в полосе как пройденные с результатом.

| Шаг | Когда открыт | Содержимое | Действия |
|---|---|---|---|
| 1 Описание | новая СТЕ | поле «вставьте как есть», зона файла, справа «что будет дальше» (4 строки) | «Заполнить карточку» (`Ctrl Enter`) |
| 2 Категория | у категории вопрос (`ktru.question`) | вопрос, до 6 вариантов: название, КПГЗ, «N из 30 похожих», 1–2 наименования и миниатюры похожих СТЕ | «Выбрать категорию», «Ни одна не подходит» |
| 3 Позиция КТРУ | у цепочки вопрос (`chain.ktru.question`) | вопрос по характеристике, варианты с кодом КТРУ и «останется N» | «Выбрать и перейти к характеристикам», «Ни одна не подходит», «Вернуться к категории» |
| 4 Характеристики | вопросов нет | группы «Общие сведения», «Обязательные», «Необязательные: ещё N» (свёрнуты); у поля — провенанс («из текста: «А4»», «ваш ответ на шаге 3», «в тексте нет») и замечание с кнопкой исправления; справа «Осталось» со ссылками на поля | нижняя полоса: «Готово N из M», «Проверить и отправить» |
| 5 Отправка | после «Проверить и отправить» | переключатель «Сводка / Как на портале»; цепочка кодов; таблица характеристик; итог проверки модерации | «Отправить на модерацию»; после — «Заявка № N у модератора», «Открыть «Мои заявки»», «Создать ещё одну СТЕ» |

**Шаг 3, когда позиции в КТРУ нет** (у категории нет ссылок на КТРУ, или ссылки есть, а позиций нет в
справочнике): шаг проходится сам с результатом «В КТРУ нет», и на нём прямо написано: «Позиции КТРУ для этого
товара нет. Код КТРУ останется пустым, характеристики оформлены в формате КТРУ». **Формат КТРУ** — как в
карточках ЕИС: название характеристики из стандарта категории, значение из её перечня, число — с единицей по
ОКЕИ полным названием, диапазон — порогами «≥ 80 и < 90»; код КТРУ не выдумывается. Если привязано N позиций, но
их нет в загруженном справочнике, подпись другая: «справочник КТРУ не содержит N привязанных позиций». Позиция
одна — шаг пройден с её кодом. Что делать с товарами без КТРУ дальше — вопрос организаторам
(`docs/tz/03-requirements.md`, раздел 5, п. 8); до ответа модуль ведёт себя как выше.

«Готово N из M» считает только обязательные характеристики позиции (`required`); «Общие сведения»
показываются, но в M не входят, пока портал не требует их явно.

**Фото товара** — необязательное поле в «Общих сведениях». Файл загружается на сервер сразу при выборе
(JPEG, PNG или WebP, до 5 МБ), хранится вместе с заявкой, его видят предпросмотр, «Мои заявки» и модератор.

**Пройденные шаги** кликабельны: шаг 2 и 3 показывают выбранный вариант и позволяют ответить заново
(повторный ответ перезаписывает поле хэша сессии). Если категорию модуль выбрал сам, шаг 2 показывает «Определена
по N из 30 похожих» и «Ни одна не подходит».

**Состояния:** загрузка после «Заполнить» — полоса шагов с текущей операцией («ищем категорию», «заполняем
характеристики»); «не найдено» — шаг 2 с объяснением и похожими позициями (`not_found_steps`); ошибка API —
текст ошибки и «Повторить»; истёкшая сессия — «Заполнить заново» с сохранённым текстом. Пакет и «Мои заявки»
открывают мастер с префиллом, как сейчас (`createModel.Prefill`).

## 5. Живая карточка (правая колонка, 340 px, с шага 2)

Вкладки «Карточка» и «Ваш текст». Карточка: «Готово N из M обязательных» и полоса; хлебные крошки категории;
наименование; коды КПГЗ, ОКПД2, КТРУ (до ответа — «ждёт ответа» кобальтом); строки «Общих сведений» и
обязательных характеристик: значение (жёлтое, если из текста), «пусто» или «выберите слева» для текущего
вопроса; ссылка «Открыть как на портале». После ответа изменившиеся строки подсвечиваются на 1,5 с (MOTION 1:
движение показывает, что изменилось). «Ваш текст»: текст поставщика с жёлтыми фрагментами; фокус на поле
обводит фрагмент, клик по фрагменту ведёт к полю (как сейчас). Телефон: колонка — нижняя шторка
«Карточка: N из M · Открыть».

## 6. Предпросмотр «как на портале»

Разметка по образцу страницы СТЕ zakupki.mos.ru (Open Sans, синий и голубой портала, вкладки капсом):
хлебные крошки полного пути категории, вкладки «Общие сведения», «Характеристики», «Доп. сведения», заголовок,
фото, «ID СТЕ: после модерации», модель, производитель, страна (пустое — «не указана, заполните на шаге 4»),
таблица характеристик, на «Доп. сведениях» — ОКПД2, КПГЗ, КТРУ, СПГЗ. Подпись над превью: «Так карточку увидят
заказчики после модерации. Цена добавляется на портале». Это превью по образцу, не страница портала.

**Фото:** своё фото поставщика (загружено в мастере и сохранено на сервере) → иначе картинка
категории с портала (так делает сам портал: нет фото у СТЕ — показывается картинка категории) с подписью
«картинка категории, пока нет вашего фото» → портал недоступен — нейтральная заглушка без битой иконки.

Контракт API меняется — `export_openapi` и `npm run gen:api` в той же задаче.

## 8. Фронтенд

Тема MUI переписывается под токены раздела 3 (MUI и Tailwind остаются: формы, списки, доступность). Новая
папка `pages/create/wizard/`: чистая функция `stepOf(out, ui) → 1..5` (какой шаг открыть), модели живой карточки
и предпросмотра (`liveCard.ts`, `portalPreview.ts`) без React; компоненты `WizardPath`, `StepDescribe`,
`StepQuestion` (общий для шагов 2 и 3), `StepCharacteristics`, `StepSubmit`, `LiveCard`, `PortalPreview`,
`FileDrop`. Переиспользуются `formModel.ts`, `createModel.ts`, `chainView.ts`, `ktruView.ts`, проверка `/check`
через 500 мс. Старые `Composer`, `KtruQuestion`, `ChainFields` удаляются после переноса.

## 10. Риски

- Портал недоступен в день показа — кэш картинок прогревается заранее, без картинок превью честно показывает
  заглушку.
- Доля категорий без картинки и без КТРУ — шаги и превью показывают это прямо, а не пустым местом.
- Время: сначала тема, мастер и живая карточка (то, что видит жюри), затем предпросмотр и фото, затем файлы и
  «Общие сведения».

## 11. Итог (07.10.2026)

Сделано по плану `2026-10-07-wizard-redesign-plan.md`, задачи 1–13, ветка `feat/wizard-redesign`. Отступления от
спецификации — строками `Ruling:` в «Журнале решений» плана, главные:

- перечни «Общих сведений» — подсказки, а не ограничение: значение остаётся как написал поставщик, новый завод
  модерацию не блокирует; на шаге 4 — ввод с подсказками;

  900 px и над полями уже;
- прокси картинок не ждёт портал синхронно: GetSku отвечал 6–27 с, ответ браузеру — не дольше `IMAGE_WAIT_S`,
  скачивание в фоне и прогрев `warm_images` перед показом;
- картинка категории портала есть у 1 из 2070 категорий: превью почти всегда показывает своё фото поставщика или
  заглушку; КТРУ у большинства категорий — «нет в справочнике» (выгрузка ЕИС неполная).

Проверка: юнит-тесты фронта и бэкенда, `frontend/e2e/flows.js` (22 шага на :8080) и `e2e/wizard.js` (регрессии
по семи ревью), axe по всем шагам без нарушений, шесть размеров экрана без горизонтальной прокрутки.
