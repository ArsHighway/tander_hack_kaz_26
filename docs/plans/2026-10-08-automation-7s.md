> Срез на дату документа. С 11.10.2026 модель — локальная `gemma-4-31b-it-Q8_0.gguf` в llama.cpp server, Ollama и облачные ключи в решении не используются ([model-choice.md](../model-choice.md)); упоминания Ollama, облачных квот и `gemma4:31b` ниже описывают состояние на тот день.

Цель (решение пользователя 08.10): процесс создания СТЕ — автоматический, вмешательств человека
меньше, ответ системы на шаг — до 7 с. Порядок задач — по договорённости «по порядку».

согласии ≥ 60 % — полнота 22,6 % (сейчас 8,3 %), точность 68,6 % (сейчас 60,6 %).

### Task 0: метрика «действий человека» в оценке

- `score_case(..., required=…)`: `required`, `required_filled` (при верной категории);
  `summary`: `question_rate` = 1 − decided, `manual_search_rate` = 1 − top5,
  `required_auto` = required_filled / required, `manual_required_per_card`,
  `zero_touch` — доля случаев «код верный без вопроса и все обязательные заполнены»,
  `latency_ms_max`, `over_7s` — доля случаев дольше 7 с.
- Приёмка: тесты `score_case`/`summary` с выведенными вручную числами; прогон базы.

### Task 1: бюджет времени LLM

- LLM — только по характеристикам **определённой** позиции (не по объединению кандидатов):
  в `prepare_session`, если код определён; иначе — в `answer`, когда ответ его определил
  (`Session.llm_for` — для какой позиции уже спросили; результат — `SessionStore.update`).
- Дедлайн `LLM_BUDGET_S` (4 с): не успела — карточка без неё, `degraded: llm`.
- 429 «usage limit» — без повторов (`LLMRateLimited` сразу); отказ сервиса — пауза LLM
  (`Deps.llm_paused_until`, как у эмбеддингов): следующие запросы не ждут.
- Приёмка: тест с медленной подделкой LLM — ответ ≤ бюджета + 1 с; тест «код не определён — LLM
  не вызывается, после ответа — вызывается один раз»; тест 429 «usage limit» — один запрос.

### Task 2: значения похожих СТЕ

- Индекс характеристик похожих СТЕ (`build_exemplars` → `exemplar_values.sqlite`, id → JSON).
- Позиция определена: 10 похожих этой категории, голос по имени и синонимам, значение проходит
  `fit_value`; ≥ 2 голоса и ≥ 60 % — в карточку с `method: "similar"` и заметкой «как у N из M
  похожих СТЕ». Пустое поле или только из текста — текст важнее.
- Приёмка: тест голосования (порог, синоним, значение вне перечня — нет); оценка на отложенной
  выборке (индекс eval — без неё): `target_recall` вверх, `target_precision` не ниже 0,6.

### Task 3: единицы — короткая запись как подсказка

Предложение пользователя: «100 см» → «1 м», «1000 кВт» → «1 МВт», «0,15 м» → «15 см» по длине
записи. В характеристике единица задана КТРУ («Длина, мм») и должна быть единой у всех СТЕ
(ТЗ: «приводит значения и единицы к единому виду») — значение остаётся в единице позиции.
Короткая запись — подсказка рядом (`CharacteristicOut.compact`: «1500 мм» → «1,5 м»), только
точный пересчёт, при равной длине — единица позиции. Префиксы м/М различаются: «мВт» — милливатт,
«МВт» — мегаватт (словарь сейчас сворачивает регистр — для мощности это ошибка в 10⁹).

### Task 4: категория без вопроса чаще при той же точности

- Кривая «доля без вопроса / точность» по `AUTO_SHARE`; сигнал «метки описания совпадают с
  характеристиками категории»; переранжирование пятёрки моделью при доле 0,4–0,7 (с дедлайном).
- Приёмка: `decided` вверх при `decided_precision` ≥ 0,85 на отложенной выборке.

### Task 5: КТРУ без вопроса, где можно; Task 6: мастер под автомат; Task 7: пакет

- КТРУ по извлечённым значениям; вопрос — только если позиции различаются тем, чего нет в тексте.
- Мастер: код уверенный и обязательные заполнены — сразу проверка; значения похожих СТЕ видны
  отдельно и принимаются одной кнопкой.
- Пакет: те же правила; значения похожих — в карточке строки, отметка в «Замечаниях».
