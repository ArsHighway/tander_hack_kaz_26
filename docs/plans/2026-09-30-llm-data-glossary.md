# План: LLM под два бэкенда, приём любых данных, словарь аббревиатур

> Срез на дату документа. С 11.10.2026 модель — локальная `gemma-4-31b-it-Q8_0.gguf` в llama.cpp server, Ollama и облачные ключи в решении не используются ([model-choice.md](../model-choice.md)); упоминания Ollama, облачных квот и `gemma4:31b` ниже описывают состояние на тот день.

Решение пользователя 30.09.2026: LLM только через API — локальный Ollama сейчас и «ручка» на арендованном GPU-сервере
потом (сервер дорогой, берём ближе к делу). Всё готовим заранее, с тестами и ручной проверкой модели. Формат данных
от организаторов неизвестен — нужен приём, который подстраивается по содержимому. Эксперты портала говорят
аббревиатурами — нужен словарь и таблица аббревиатур из их базы.

### Task 1: Клиент LLM с двумя провайдерами
- `app/llm/`: `LLMClient` — `chat(messages, schema=None) -> ChatResult`, `embed(texts) -> list[list[float]]`,
  `list_models() -> list[str]`. Провайдеры: `ollama` (нативный `/api/chat`, `/api/embed`, `/api/tags`, JSON-схема
  в `format`) и `openai` (OpenAI-совместимый `/v1/chat/completions`, `/v1/embeddings`, `/v1/models` — vLLM,
  llama.cpp server, Ollama `/v1`; Bearer-токен по желанию).
- Эмбеддинги можно брать у другого провайдера, чем чат (`EMBED_*` по умолчанию = `LLM_*`).
- Правила вывода исполняет код: вырезать `<think>` и ```-ограды, валидировать pydantic-схемой, иначе
  `LLMOutputError`. Повторы на сетевых ошибках, 429 и 5xx.
- Тесты на `httpx.MockTransport`: форма запроса каждого провайдера, разбор ответа, think-теги, битый JSON,
  повтор после 503, заголовок авторизации.

### Task 2: Ручная проверка модели
- `python -m app.tools.llm_smoke`: русский ответ, извлечение характеристик в JSON по схеме, понимание аббревиатур,
  здравый смысл эмбеддингов (похожие товары ближе непохожих). Таблица: случай, ок, задержка, вывод; код выхода ≠ 0
  при провале. Одинаково работает против локального Ollama и сервера — меняется только `.env`.

### Task 3: Приём данных неизвестного формата
- `app/ingest/readers.py`: csv (кодировка utf-8/cp1251, разделитель — по содержимому), xlsx (потоково, строка
  заголовка — первая с ≥2 непустыми ячейками, хвостовые пустые колонки отбрасываются), json/jsonl, zip/7z (распаковка
  во временную папку).
- `app/ingest/characteristics.py`: строка «Имя:Значение;…» (Пермь), «Имя:Значение Ед;…» (Казань 2025), список пар,
  список объектов, словарь. Единица из имени («Толщина, мкм»), число с запятой и хвостовыми нулями, диапазоны
  («0.005 - 30», «в диапазоне от 0 и до 0,5», «больше или равно 200»), да/нет. Непонятный кусок — сырой текст с
  флагом, без угадывания.
- `app/ingest/profile.py` + `python -m app.tools.recon <путь>`: инвентарь файлов, листы, колонки, заполненность,
  примеры и роль колонки по содержимому (id, наименование, категория, производитель, характеристики, код КТРУ,
  ОКПД2, КПГЗ, единица, цена, дата, ИНН), статистика ключей характеристик.

### Task 4: Словарь аббревиатур
- `app/glossary/abbreviations.csv` (наш, коммитится): аббревиатура, расшифровка, вид (закупки, единицы, материалы,
  техника, медицина, организации).
- `expand(text)` — подписывает расшифровку к аббревиатуре целым словом для LLM и эмбеддингов.
- `mine(texts)` — кандидаты из данных организатора: заглавные токены, шаблон «полное название (АББР)», частоты и
  примеры контекста → CSV и таблица `glossary_abbreviation` (источник `seed` / `mined` / `manual`).
- Миграция на таблицу, `python -m app.tools.mine_abbreviations`.

### Task 5: Фейковый датасет
- `scripts/make_fake_dataset.py` (seed) → `tests/fixtures/fake/`: СТЕ в xlsx (как в Перми), csv в cp1251 с `;`,
  jsonl с парами; справочник КТРУ в json (вложенный) и csv (длинный); `ground_truth.json` с ожидаемыми кодами и
  внесёнными ошибками (опечатка, значение вне перечня, чужая единица, аббревиатура, белая против цветной бумаги).
- Тесты приёма и профиля гоняются на этих файлах; на хакатоне те же инструменты — на настоящих данных.
