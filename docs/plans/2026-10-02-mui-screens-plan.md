# Экраны модуля на новом дизайне (MUI, форма вместо отчёта)

Решение пользователя 02.10.2026: прототип `/preview` утверждён, все экраны переводятся на него и подключаются к
живому API. Исполняет эта же сессия, ветка `feat/mui-screens`.

**Цель:** каждая кнопка на экранах работает на живом `/api/v1` и `/api/demo`.
**Архитектура:** MUI (тема `src/theme.ts`, слои CSS: `GlobalStyles` с `@layer theme, base, mui, components, utilities`
первым ребёнком `StyledEngineProvider enableCssLayer`), Tailwind только для раскладки. Логика экранов в чистых
TS-модулях с тестами `node --test`; вёрстка в TSX без логики.

## Глобальные ограничения

- В тексте интерфейса нет длинного тире; кнопка — глагол; одна заливная кнопка на экран.
- Нерабочих кнопок нет: чего не умеет API, того нет на экране.
- Значение из текста поставщика подсвечено жёлтым (`#fff9db` у поля, `#ffe98f` во фрагменте) с подписью источника.
- Ошибка показывается на поле; исправление делается в этом же поле или кнопкой из `issue.fix`.

## Task 1: модель формы `src/pages/create/formModel.ts` (TDD)

Контракты:
- `buildFields(chars: CharacteristicOut[], position: Position | null): FieldState[]`: перечень значений из
  `position.characteristics[].values` (по имени без учёта регистра), единица из ответа или спецификации, обязательность —
  из ответа или спецификации.
- `mergeFields(prev, next)`: после ответа на вопрос значение, изменённое человеком (`value !== initial`), остаётся.
- `cardFrom(name, description, fields, ktruCode): CardIn`: в карточку идут только непустые значения.
- `acceptedFrom(fields): CharacteristicOut[]`: изменённое человеком без `source`, со статусом `filled`.
- `issuesByField(issues)`: `name` → наименование, `characteristics.X` → поле X, остальное — общим списком.
- `fieldHelper(field, issue?)`: подпись под полем (ошибка, «Изменено вами», «Из описания: «…»», приведение, ответ).
- `blocking(issues, fields)`: число того, что мешает отправке: замечания `block` плюс пустые обязательные поля без замечания.
- `splitPasted(text)` / `joinPasted(name, description)`: первая непустая строка — наименование, остальное — описание.

## Task 3: «Создание СТЕ»

Стартовый экран (одно поле, примеры) → `api.autofill` → форма. Позиция: `api.ktru(final_code)` для перечней.
Вопрос КТРУ (`ktru.question`) — блок над формой с вариантами (`optionLabel`), ответ — `api.answer` и `mergeFields`.
Правка поля → проверка `api.check` с задержкой 500 мс. «Отправить» → `api.check`; при блокирующих замечаниях не
отправляет, иначе `api.submit` и экран «Заявка № N отправлена» со ссылкой в заявки. Справа — исходный текст с
подсветкой фрагментов, фокус поля обводит его фрагмент. Префилл из массовой загрузки (`PREFILL_KEY`).

## Task 4: «Заявки» (модератор)

`api.submissions` → очередь со статусами; выбор → `api.submission(id)`: карточка только для чтения с замечаниями на
полях, текст возврата `returnNote`, «Вернуть с замечаниями» / «Одобрить» → `api.decide`. `?id=` в адресе.
