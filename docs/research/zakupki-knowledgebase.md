# База знаний Портала поставщиков: что в ней и что берём в модуль

Выгружена 06.10.2026: `uv run python -m app.tools.fetch_knowledgebase --out ../data/knowledgebase` (из
`backend/`, 4 запроса с паузой 1 с, 8 с на ПК). Источник — тот же публичный API, что у страницы
https://zakupki.mos.ru/knowledgebase/main/supplier: `GET /newapi/api/KnowledgeBase/GetArticlesBySectionType?sectionType=…`
(robots.txt закрывает только `/api` и `/admin`). Данные портала лежат в `data/knowledgebase/` (вне git):

| Файл | Что |
|---|---|
| `raw/<раздел>.json` | ответы API как есть: `supplier`, `customer`, `instruction`, `general` |
| `articles.jsonl` | статья на строку: `id` (он же в адресе на сайте), `title`, `url`, `sections`, `category`, `service`, `topics`, `updated`, `text`, `operator_text`, `files`, `tags` |
| `<раздел>/<id>-<slug>.md` | статья в Markdown с фронтматтером; текст для оператора поддержки отдельным разделом, если отличается |
| `index.md` | оглавление: раздел → категория → статьи со ссылками на файл и на сайт |

Перевыгрузка без сети из сохранённых ответов: `--raw ../data/knowledgebase/raw`.

## Объём

516 статей в четырёх разделах, без повторов 483 (одна статья бывает в нескольких разделах): для поставщика 252,
для заказчика 45, инструкции 157, общий раздел 62. Текст есть у всех 483. У 152 статей (31 %) текст для
оператора поддержки отличается от текста для пользователя: он короче и жёстче формулирует правила («должно быть
в единственном числе», «без сокращений»), поэтому сохраняем и его.

По теме кейса (СТЕ, характеристики, модерация, единицы, оферты) — 112 статей; самое плотное — категории
«Работа с СТЕ» (64) и «Работа с СТЕ и офертами» (30).

## Правила карточки СТЕ из базы знаний против наших проверок

| Правило портала | Статья | У нас |
|---|---|---|
| Не меньше 4 характеристик, иначе заявку не отправить; при 4 «высока вероятность возврата» | [214357](https://zakupki.mos.ru/knowledgebase/article/details/ais/214357), [214359](https://zakupki.mos.ru/knowledgebase/article/details/ais/214359) | есть: `min-chars` (block) |
| Единица количественной характеристики — в поле единицы, не в названии и не в значении | [214359](https://zakupki.mos.ru/knowledgebase/article/details/ais/214359), [214146](https://zakupki.mos.ru/knowledgebase/article/details/ais/214146) | есть: `unit-in-char-name`, разбор единиц из значения |
| У качественной характеристики единицы нет; значение — текст или «да/нет» | [214369](https://zakupki.mos.ru/knowledgebase/article/details/ais/214369), [214156](https://zakupki.mos.ru/knowledgebase/article/details/ais/214156) | да/нет извлекаем; отдельного замечания «единица у качественной» не нашёл |
| Нет дублей и характеристик, не свойственных товару | [214359](https://zakupki.mos.ru/knowledgebase/article/details/ais/214359) | есть: повторённые имена (`hygiene`), «нет в позиции КТРУ» |
| Обязательные характеристики категории заполнены | [214209](https://zakupki.mos.ru/knowledgebase/article/details/ais/214209) | есть: `RULE_REQUIRED` в детекторе |
| Наименование: ЧТО + НАЗНАЧЕНИЕ + БРЕНД + МОДЕЛЬ + 1–2 характеристики, числовые раньше текстовых | [214362](https://zakupki.mos.ru/knowledgebase/article/details/ais/214362) | частично: «наименование называет товар», числа с единицами из наименования уходят в характеристики |
| Наименование не начинается с артикула | [214362](https://zakupki.mos.ru/knowledgebase/article/details/ais/214362) | **нет** |
| В наименовании нет рекламы: «акция», «скидка», «распродажа», «черная пятница», «лучший товар» | [214362](https://zakupki.mos.ru/knowledgebase/article/details/ais/214362) | **нет** |
| Наименование не целиком на иностранном языке | [214362](https://zakupki.mos.ru/knowledgebase/article/details/ais/214362) | **нет** (латиница только чинится в кириллическом слове) |
| Без сокращений; для товаров слово «Поставка» не нужно; работы и услуги начинаются с вида работ («Монтаж», «Изготовление») | [214362](https://zakupki.mos.ru/knowledgebase/article/details/ais/214362) (текст оператора) | сокращения раскрываем словарём для поиска, замечания нет; остальное **нет** |
| Поле «Модель» не «-», «нет», «Ассорти», «В ассортименте», «#» | [214361](https://zakupki.mos.ru/knowledgebase/article/details/ais/214361) | поля «Модель» в нашей карточке нет |
| Описание необязательно, ценообразующие характеристики в нём не учитываются при сопоставлении СТЕ | [214361](https://zakupki.mos.ru/knowledgebase/article/details/ais/214361) | совпадает с идеей модуля: переносим характеристики из описания в поля |
| Категория — только конечная в дереве | [214343](https://zakupki.mos.ru/knowledgebase/article/details/ais/214343) | позиция КТРУ у нас всегда конечная |
| Отклонение «Предложена другая СТЕ», если похожая есть на 70–100 % | [214102](https://zakupki.mos.ru/knowledgebase/article/details/ais/214102) | **нет**: проверки дубля против каталога нет |
| Срок рассмотрения заявки — до 5 рабочих дней | [214236](https://zakupki.mos.ru/knowledgebase/article/details/ais/214236) | аргумент за проверку до отправки (меньше возвратов) |
| Возвращённую заявку правят по комментарию модератора и отправляют снова | [214022](https://zakupki.mos.ru/knowledgebase/article/details/ais/214022) | есть с 05.10.2026: «Мои заявки» → «Исправить» |

Из этого прямо следует: связи СТЕ с КТРУ на портале нет «технически» ([451729](https://zakupki.mos.ru/knowledgebase/article/details/ais/451729):
КТРУ описывает категорию без бренда, СТЕ — конкретный товар). Модуль, который предлагает позицию КТРУ по
характеристикам СТЕ, закрывает именно этот разрыв.

## Что можно сделать дальше

1. Три правила наименования без справочника: артикул в начале, рекламные слова, наименование целиком
   латиницей. Перед включением прогнать по `data/testset/` на ложные срабатывания, как остальные правила.
2. Замечание «единица у качественной характеристики».
3. Поиск похожих СТЕ перед отправкой (порог 70 % из статьи 214102) — по каталогу портала, если он будет в данных
   организаторов.
4. Статьи как источник ответов в подсказках: под замечанием ссылка на статью портала, которая его объясняет.
