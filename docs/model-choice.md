# Выбор модели LLM

## Решение на сдачу (11.10.2026)

Модель — локальная **`gemma-4-31b-it-Q8_0.gguf`**: llama.cpp server (сервис `llm` в `docker-compose.yml`,
профиль `llm`), OpenAI-совместимый API, `LLM_CHAT_MODEL=gemma-4-31b-it-Q8_0`. Тот же сервер и та же модель
работают вторым слоем проверки (`LLM_REVIEW_MODEL`). Эмбеддинги — `bge-m3-Q8_0.gguf` во втором экземпляре
llama.cpp server (сервис `embed`). Облачные API и Ollama в решении не используются, данные организаторов с
машины не уходят. Файлы лежат в `models/`, запуск — `docker compose --profile llm up -d` (`models/README.md`).

Почему так: одна модель закрывает чат, второй слой и порядок типов; сервер один и тот же в разработке и на
стенде; нет квот и 429 облачного тарифа, из-за которых 08.10 и 09.10 модель отключалась.

Чего не проверяли. Замер ниже снят на `gemma4:31b` из Ollama API (04.10.2026), с файлом
`gemma-4-31b-it-Q8_0.gguf` на карточках портала его не повторяли: это тот же класс модели (Gemma 4, 31 млрд
параметров), но другая сборка и квантование Q8_0, поэтому цифры полноты, точности и задержки ниже — оценка, а не
замер этого файла. Проверка соединения и схемы ответа — `uv run python -m app.tools.llm_smoke`. Результат
второго слоя на той же gemma может отличаться от замера 10.10, где его вела `gpt-oss:120b` из облака
(`docs/qa/2026-10-11-hard-gold.md`).

## Замер 04.10.2026: выбор семейства gemma4:31b

Через API Ollama (адрес и ключ в `.env`, облачный бесплатный тариф) выбрана **gemma4:31b**: среди моделей
тарифа она находила больше всего значений и реже всех ошибалась, при задержке 0,8 с.

## Что модель делает в модуле

Правила извлекают значения из наименования и описания. Модель получает только то, что правила не нашли:
наименование, описание и спецификации оставшихся характеристик. Её ответ проходит проверку кодом
(`extract/llm_fill.py`): имя должно быть среди характеристик позиции, цитата — дословно в тексте и
содержать значение, значение — подходить к перечню или диапазону. Поэтому мерить нужно ровно эту работу,
а не общий чат.

## Как мерили

`uv run python -m app.tools.compare_models ../data/testset/testset.jsonl --models … --cards 120`
(из `backend/`, кэш ответов выключен, `LLM_CACHE_TTL_S=0`).

- Карточки — тестовый набор с публичного API Портала поставщиков (5 000 СТЕ, `app.tools.build_testset`).
  Из них взяты те, где правила пропустили хотя бы одно значение, которое видно в тексте: таких 2 778,
  в выборке 120 (seed 42), пропущенных значений — 240. У всех моделей одни и те же карточки.
- Эталон — значение, которое поставщик указал на портале; сравнение `same_value` с пересчётом единиц.
- Полнота — доля из 240 значений, которые модель нашла верно после проверки кодом. Точность — доля верных
  среди принятых кодом. «Отвергнуто кодом» — элементы ответа, которые не прошли проверку (выдуманная
  цитата, значение не из перечня).
- Рассуждения выключены (`LLM_THINK=false`), у gpt-oss — `low` (выключить их нельзя).

## Результат (04.10.2026)

| Модель | Найдено верно (полнота) | Точность | Предложено / отвергнуто кодом | Ошибок схемы | Задержка p50 / p95, мс |
|---|---|---|---|---|---|
| **gemma4:31b** | **118 из 240 (49,2 %)** | **77,6 %** | 171 / 19 | 0 | 804 / 1 404 |
| gpt-oss:120b | 92 из 240 (38,3 %) | 73,6 % | 194 / 69 | 0 | 797 / 1 231 |
| nemotron-3-nano:30b | 81 из 240 (33,8 %) | 65,9 % | 241 / 118 | 2 | 9 947 / 35 685 |
| gpt-oss:20b | 80 из 240 (33,3 %) | 63,5 % | 171 / 45 | 2 | 1 863 / 3 086 |
| glm-5.3-flash, deepseek-v4.1-flash, minimax-m2.7 | недоступны на бесплатном тарифе (402) | | | | |

- gemma4:31b находит на 26 значений больше gpt-oss:120b, а код отвергает у неё втрое меньше элементов
  (19 против 69): модель реже придумывает цитаты и значения вне перечня.
- gemma4:31b меньше gpt-oss:120b по числу параметров: 31 млрд против 120 млрд.
- На золотом наборе (`app.tools.evaluate --llm`) модели неразличимы: полнота заполнения 97,2 % у
  gemma4:31b и 97,5 % у gpt-oss:120b на шаблоне, 100 % и 99,6 % на реальных форматах, остальные метрики
  совпадают. Правила там находят почти всё сами, поэтому выбор сделан по карточкам портала.
- `llm_smoke` с gemma4:31b: 5 из 5 (русский ответ, извлечение в JSON, аббревиатуры, эмбеддинги).

## Ограничения замера

- 120 карточек, одна выборка: gemma4:31b и gpt-oss:120b различаются на 26 значений из 240, а
  gpt-oss:20b и nemotron-3-nano:30b — на одно, их порядок между собой случаен. Статистический тест
  не проводили.
- Эталон поставщика сам бывает ошибочным: часть «неверных» значений может быть верной в тексте.
  Сравнение моделей это не искажает — у всех один эталон.
- Бесплатный тариф Ollama API держал около 0,8 запроса в секунду на ключ, а 08.10 ключ упёрся в «Free usage
  limit» на ~8,4 тыс. запросов за 2 ч (у тарифа лимиты на 5 часов и на неделю). Этот предел и ушёл вместе с
  облаком: локальный сервер ограничен GPU и числом слотов (`LLM_PARALLEL`), а не тарифом. С хоста сервер звать по
  `127.0.0.1`: на Windows `localhost` сначала пробует IPv6 и теряет 2 с. В массовой загрузке модель — узкое место
  (`docs/scaling.md`). Повторы на 429 и общий лимит одновременных запросов
  (`LLM_RATE_LIMIT_RETRIES`, `LLM_MAX_CONCURRENCY`) не дают строкам терять значения модели.

## Хаос в описании (11.10.2026)

`uv run python -m app.tools.llm_chaos --cases 40 --models gemma4:31b gpt-oss:20b gpt-oss:120b …`
(из `backend/`). 40 СТЕ хакатона из отложенной выборки, 117 значений поставщика; описание испорчено
как у торопливого поставщика: одна строка, опечатки в 30 % слов от 5 букв, метки без «Вид»/«Тип» и без
двоеточия, «кол-во», «р-р». Полнота — доля значений поставщика, которые попали в своё поле верно.
Задержка — все вызовы модели на товар.

| Вариант | Полнота | Точность | p50 / p95, с |
|---|---|---|---|
| правила, чистый текст (потолок) | 85,5 % | 86,2 % | — |
| правила, испорченный текст | 51,3 % | 84,5 % | — |
| gemma4:31b — дозаполнение пустых полей | 74,4 % | 86,1 % | 2,8 / 8,3 |
| gemma4:31b — исправление текста, затем правила | 63,2 % | 86,0 % | 2,6 / 3,5 |
| gemma4:31b — исправление + дозаполнение | 76,9 % | 87,4 % | 5,6 / 6,7 |
| gpt-oss:120b — исправление + дозаполнение | 78,6 % | 87,6 % | 10,7 / 13,0 |
| gpt-oss:20b — исправление + дозаполнение | 76,1 % | 89,0 % | 38,1 / 52,7 |
| nemotron-3-nano:30b — исправление + дозаполнение | 64,1 % | 85,2 % | 63,1 / 216,9 |

- deepseek-v4.1-flash и glm-5.3-flash на бесплатном ключе не отвечают («timed out waiting for a
  concurrent request slot»).
- Локальная qwen3.5:9b на ПК разработчика — 1,8 токена/с (видеопамять занята), запросы упираются в
  60 с; на сервере стенда видеокарты нет. Локальную модель не берём.
- Тип КТРУ на тех же 40 СТЕ (`evaluate_holdout`, без модели в конвейере): чистый текст — верный первым
  87,5 %, испорченный — 85 %, после исправления gemma4:31b — 87,5 %; значения поставщика после ответа
  на вопросы — 58 % / 40 % / 51 %.

**Вывод:** gemma4:31b, два вызова — исправление текста до поиска и дозаполнение пустых полей после выбора
позиции. На товар около 6 с (p95 меньше 10 с), полнота на хаосе 51 % → 77 % при той же точности.
gpt-oss:120b даёт на 1,7 п. п. больше, но вдвое дольше.
